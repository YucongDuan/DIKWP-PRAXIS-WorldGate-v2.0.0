本版把任务证据、有限权限、库存状态、操作预算、结果观察和补偿条件连接为一套实际运行的协议。它不要求先相信某个模型“足够聪明”，而是要求每次受控操作在当下满足已声明条件。

# 1　逐项升维：从判断转向控制
上一版已经包含任务合同、工具读取权限检查、轨迹核验、局部发布登记和结果重开。新版没有把这些既有功能抹去，以制造虚假的比较优势。对照基线是实际恢复的v1源码与测试，而非一个弱化的假想产品。[B1]

| 维度 | v1实际基础 | WORLDGATE新增 |
|---|---|---|
| 评估与行动 | 本地评测与发布状态登记 | 对真实本地库存进行受控修改 |
| 权限时点 | 简单读取代理＋事后轨迹检查 | prepare和commit两阶段均检查 |
| 批准凭证 | 共享密钥HMAC | 不同公钥的Ed25519角色签名 |
| 证据有效期 | 版本化资格记录 | 过期与撤销直接影响后续提交 |
| 并发竞争 | 每次评估新建环境 | 同一事务中检查版本和剩余额度 |
| 重试 | 保留失败记录 | 请求ID与完整载荷绑定，回执复用 |
| 回退 | 局部发布状态回退 | 满足当前状态条件才执行反向库存操作 |
| 完成判定 | 声明的后置条件 | 只读观察者签名与实际库存核对 |

核心变化是将“评估结果作为报告”进一步变为“评估证据参与某个有限行动的准入”。通过证据仍不会自动签发授权；签发授权也不能跳过提交时的状态检查。

唯一实际副作用适配器为 inventory.reserve。对任意文件、数据库、浏览器、云平台和支付接口的全面控制仍未实现。

# 3　六类角色、四种权力与一条执行链
## 角色不是模型自己填写的头衔
| 角色 | 可以签署或执行的对象 |
|---|---|
| owner | 目的、资源、最低库存和单次操作边界 |
| evaluator | 限定范围的评测证据及其期限 |
| reviewer | 授权内容的独立审核签名 |
| operator | 与审核内容完全一致的执行批准及撤销、补偿 |
| executor | 具体操作请求，不持有审核批准权 |
| observer | 从只读数据库获得的实际后置状态 |

审核者、操作员、执行者和合同所有者必须是四个不同的配置主体；同一公钥不能复制为不同身份。这个检查阻止简单的密钥别名伪装，但不能验证两把私钥背后是否真是两个自然人。身份登记与密钥保管仍需组织制度。[S3]

## 执行链
```text
owner contract → evaluator evidence
                  ↓
reviewer + operator → finite grant
                  ↓
executor proposal → PREPARED
                  ↓  recheck under transaction
COMMITTED_PENDING_OBSERVATION
                  ↓  read-only observer
VERIFIED_LOCAL_EFFECT / RECONCILIATION_REQUIRED
```

四种权力分开：定义目的、判断证据、批准操作、观察结果。默认不提供任意shell或网络调用接口。操作代理必须部署在资源权限边界，不能只是给一个同时持有数据库管理员密码的智能体增加“建议性提示”。

# 4　把“任务”编译为不可含混的操作合同
合同限定操作类型、资源集合、候选版本哈希、最低库存、单次数量和最长租约。证据进一步绑定合同与候选版本、评测范围、来源、案例组数、结果文件哈希和有效期。授权由审核者与操作员对完全相同的载荷分别签名。

## 可执行请求示例
```json
{
  "kind": "action", "tenant": "local",
  "action_id": "request-001", "actor": "executor-person",
  "grant_id": "grant-001",
  "contract_hash": "<reviewed SHA-256>",
  "candidate_hash": "<reviewed SHA-256>",
  "operation": "inventory.reserve",
  "resource": "stock-a", "units": 3,
  "expected_revision": 0
}
```
示例中的尖括号是需要替换的说明，不是有效哈希。程序拒绝布尔值冒充整数、浮点数量、负数、额外指令字段、未列出的操作，以及租户、候选、合同或资源替换。签名并不会使错误载荷获得资格。

## 必须保留的区别
candidate_hash绑定的是被批准的候选声明；本版不提供远程二进制执行证明。artifact_hash指向评测材料；评估器签名不证明该材料的事实一定真实。旧版订单汇总测试也不能自动授权新版库存操作：操作合同不匹配时拒绝。

所有真实CLI调用使用主机时间。SDK中的测试时钟和故障注入参数属于受信任测试驱动，不进入操作请求模式。

# 5　原子提交：把检查和结果放入同一现实边界
prepare只登记请求及预测的前后状态，不扣减库存、不占用额度。commit取得写事务后重新核验：授权仍有效、证据未撤销、租约未过期、资源版本未变化、操作和总额度仍有余量、最低库存不被突破。[S1—S2]

```text
BEGIN IMMEDIATE
  verify authority + evidence + time
  compare current state with prepared state
  verify quantity + remaining quota + floor
  update inventory and revision
  charge grant counters
  persist effect receipt and audit event
COMMIT
```

## 局部不变量及证明思路
设库存为x，申请量u，底线m，已用额度b，总额度B。允许提交必须同时满足 x−u≥m 与 b+u≤B。检查与更新由同一个受信任事务串行化，因此下一提交看到的是已更新状态，而不是先前读到的余额。

在数据库事务原子性、可信适配器和可信存储成立时，可对成功提交次数归纳：底线不被有效提交突破；计数不超过授权；相同租户和请求ID不能产生第二次库存效应。这个结论不是对任意硬件崩溃、管理员篡改或跨服务事务的全局证明。

## 已执行的并发试验
24个不同请求先prepare，再由8个线程争用一次额度。结果是1次COMMITTED_PENDING_OBSERVATION、23次GRANT_BUDGET_EXHAUSTED，库存100变为97。不是24个线程都拿到一个“通过”标签以后再补查。

# 6　结果观察：接口返回成功以后还没有结束
执行回执包括请求哈希、候选与证据引用、原状态、预测后状态以及提交时间。此时只结算为COMMITTED_PENDING_OBSERVATION。观察者通过只读连接读取实际状态，签署请求和回执绑定的观察记录；代理再与当前数据库核对。

| 观察情况 | 结算 |
|---|---|
| 实际状态与提交后状态相同 | VERIFIED_LOCAL_EFFECT |
| 有后续写入，状态不再相同 | RECONCILIATION_REQUIRED，暂停该授权 |
| 观察之后、接收之前状态又变化 | OBSERVER_SNAPSHOT_NOT_CURRENT |
| 执行者自己使用执行密钥声称成功 | 观察角色检查拒绝 |

本次测试实际启动了一个独立CLI进程，用观察者密钥和只读数据库连接生成回执，再由主进程核验。这比信任智能体输出中的success=true更强，但仍不等于不同机构、不同硬件或独立传感器的事实认证。

## 不将正常竞争误写成恶意
库存先从100变为97，随后另一个合法动作把它变为92。此时对第一个动作进行观察，当前库存不再是97。系统要求核对历史及并发关系，不直接宣布第一个动作欺骗，也不把第二个动作的结果覆盖掉。

签名验证来自经过维护的密码库，而不是自行实现签名数学。它证明记录来自配置公钥所对应的私钥持有者，不证明该观察者不会撒谎。[S3]

# 7　失败、结果未知与补偿是三种不同状态
## 提交前后的故障不应混为一次失败
在提交前注入故障，库存、额度和回执整体回滚。提交后回复丢失，则库存已经改变；相同请求重试只返回原回执，不再次扣减。演示通过重新打开数据库验证了这两条路径。

## 两服务之间没有自动获得原子性
额外实验使用两个真实本地SQLite数据库，分别代表调用端与提供端。它不是网络连接器，但故意保留了跨边界间隙。

| 场景 | 提供端实际效应 | 调用端处置 |
|---|---|---|
| 扣减7后回复丢失 | 存在一次效应 | UNKNOWN；禁止盲重试，查询后确认 |
| 返回成功却未执行 | 没有记录 | 不签发完成；要求重试授权审查 |
| 发送前进程停止 | 没有记录 | 核对后进入RETRY_AUTHORIZATION_REQUIRED |
| 状态接口不可用 | 无法判断 | 保持UNKNOWN，不将未知当失败 |

参考结果中提供端仅执行一次，库存100变93。没有把HTTP 200或相似确认文字当作实际完成的证据。

## 补偿不覆盖后来者
补偿仅在当前完整状态等于原动作记录的后状态时执行；恢复数量但递增版本，并保留原回执。后来已有写入就返回COMPENSATION_CONFLICT。操作预算不返还，防止通过反复撤回刷新调用额度。对跨服务、物理行动或不可逆操作，本版不承诺能够补偿。

# 8　签名、信任根、重执行与DIKWP责任链
## 必须在包外保留的东西
导出包包含公钥登记和签名锚，但“包里有自己的公钥”不能证明外部来源。replay支持--trust加载独立保留的公钥根；未提供固定根时，只报告自包含签名完整性，不声称已认证来源。即使固定了根，攻击者若整体回退数据库和旧的有效锚，也需要一份包外最新锚才能被识别。

## 不只检查哈希
回放在新的临时数据库中，从初始资源开始重新执行成功的签名合同、证据登记、授权、prepare、commit、观察、补偿和撤销。每一步重算结果哈希，最后对照库存、动作、授权计数及证据活动状态。截断签名历史和仅修改最终库存都在实验中被检测到。

拒绝记录为了减少内容暴露仅保存原请求哈希，所以不会宣称重新执行了那些拒绝的原始输入。回放也不是重新调用原智能体，更不是再次观察物理世界。

## DIKWP的可操作映射
D登记输入、证据及观察；I登记拒绝、冲突和撤销；K登记限定范围的执行回执；W通过批准的资源、额度及底线约束实际影响准入；P登记目的和具体动作。事件之间给出真实源、目标和生成内容。

系统允许25类有向路线，但只声称参考事件实际出现的路线。反向重执行给出本地状态对应关系，不由此推出所有语义、认知或现实问题已经闭合。

# 9　连续风险：固定一次阈值，而不是反复挑选显著结果
新版保留原有固定样本统计，同时增加一个有明确前提的序贯监测器。设第g组失败为Xg∈{0,1}。零假设是：给定已经观察的历史，下一组的条件失败概率不超过p0。对预先固定的q>p0，定义：

```text
L_t(q) = product_g (q/p0)^Xg × ((1-q)/(1-p0))^(1-Xg)
E_t    = mean over the fixed alternative set of L_t(q)
alarm  = first t with E_t >= 1 / alpha_stream
alpha_stream = family_alpha / predeclared_family_size
```

若真实条件失败概率pt≤p0，一步乘子的条件期望等于1+(pt−p0)(q−p0)/(p0(1−p0))≤1。因此L及固定混合E为非负测试超鞅；在前提成立时，Ville界控制任意时点跨阈值的概率。多条预声明流使用误差预算分配及联合界。这是既有安全任意时点推断思想的具体应用，不是新发明的统计定理。[S4]

参考p0=.05，备择q=[.1,.2,.4,.7]，family_alpha=.05，family_size=2，阈值为40。前10组不失败、后15组失败的合成序列在第15组首次触发。全不失败序列只得到“未拒绝零假设”，不是安全证书。

缺失第6组结果时只处理前5组，后面的快结果不得越过该缺口。配置、分组、顺序、备择和监测家族必须在看结果之前确定；组标签不能证明总体代表性。一个严重单次事件无需等到统计显著才暂停操作。

# 10　可控修复：允许提出新规则，不允许自己改写考试
本版实现一个可以复现的有限规则搜索，而不是声称“模型自动进化”。待修复的库存提议器有三项布尔规则：严格整数、遵守库存底线、忽略来源文本中的指令。三个开关构成8个候选；每个候选在36个开发案例上实际执行。

基线三开关全关时正确15/36。程序先在开发集选择达到全部声明断言且改动数最少的候选，再把候选哈希写入一次性保留集账本，之后才执行36个不同种子生成的保留案例。选中的三个开关全开策略在本次保留案例上达到36/36。

| 控制 | 实际行为 |
|---|---|
| 候选形成 | 预实现的8种规则组合，不生成任意代码 |
| 选择依据 | 仅开发集，不使用保留集选择候选 |
| 消耗时点 | 评估保留集前先登记候选和数据哈希 |
| 再试一次 | 同一修复家族再次请求被拒绝 |
| 部署资格 | 不自动签发授权，不自动替换生产策略 |

保留集仍是公开合成数据；本地账本也不能阻止管理员复制或清空数据库。它防止正常工作流中的无痕复用，不声称提供对恶意管理员的隐藏考试系统。

## 将大失败压缩成可理解的反例
另一个模块在限定查询预算内逐条删除输入，只要失败仍然存在就继续压缩。四条订单被压缩为一条金额11的取消订单，仍足以证明“不区分取消状态”的汇总规则错误。它达到当前失败谓词下的删除极小，不代表所有表示下的全局最小反例。

## 风险发现怎样影响下一次权限
在额外反馈演示中，风险监测结果产生一个未签名撤销提案；另一个合成操作员角色对其签名。系统据此撤销指定证据及派生授权，随后新的库存请求被拒绝。它真实改变了本地授权状态，但不表示发生过自然人的批准或真实生产事故。

该反馈演示独立于上述23场景；不能把重复使用的合成监测输入当作新的独立统计样本。所有结果均可在 outputs/reference/ 中定位，测试总数也不把一项测试中的多个断言重复计数。

# 12　故障目录与可证伪条件
23个场景不是“覆盖一切攻击”的比例估计，而是针对已声明控制的回归试验。

| 故障类别 | 参考结果及重新打开条件 |
|---|---|
| 签名载荷改变 | BAD_SIGNATURE；任何改变仍通过即失败 |
| 租户、候选、资源替换 | 拒绝；跨范围生效即失败 |
| 负数、布尔、浮点或隐藏指令 | 类型/字段拒绝；无痕强制转换即失败 |
| prepare后过期或撤销 | commit拒绝；旧资格继续生效即失败 |
| 读写间状态变化 | WORLD_CHANGED；覆盖新状态即失败 |
| 提交前崩溃 | 全部回滚；部分扣减或扣额度即失败 |
| 提交后丢失回复 | 仅复用旧回执；二次扣减即失败 |
| 后续写入后的补偿 | 冲突停止；覆盖后来者即失败 |
| 并发额度争用 | 一次额度只允许一次生效 |
| 签名历史截断或最终状态伪改 | 核验或重执行失败 |

## 当前无法排除的反例
若不可信智能体仍持有原始数据库或管理员权限，它可以绕过代理；若评估器签署了虚假证据，签名无法恢复事实真相；若观察者读取的是被共同篡改的数据源，“独立密钥”也不是独立现实证据；若整体数据和旧锚一并回退，而外部没有保存更新记录，系统不能知道世界已被回退。

这些反例不是文字免责后继续宣布“全面安全”，而是部署准入清单的组成部分。任一关键假设不成立，操作者应缩小作用范围或停止真实接入。

# 14　落地路径：先控制一项资源，再增加适配器
## 阶段A：本地复验
运行全部测试与参考实验，核对源码谱系；故意改变请求、证据、权限、状态和回执，确认失败不会被重试或平均指标掩盖。仅使用合成或已获授权的非敏感数据。

## 阶段B：团队拥有的非关键资源
选择一个确实由团队控制的资源和一个可补偿操作。代理、密钥和数据库运行在智能体不能直接访问的服务账号中。分别落实所有者、审核、操作员和观察者的真实身份与保管制度，定义可信时间、日志保留、隐私、告警和人工协调负责人。

## 阶段C：有额度的小范围接入
先运行不产生业务副作用的提案阶段，再由具名操作员批准有限额度。新增适配器必须声明：幂等键、状态查询、作用域、观察位置、事务边界、补偿前置条件、超时状态、敏感数据规则和停止方式。外部接口不满足这些条件时，不应只因为其提供了API就自动接入。

## 普通团队可以先用在哪些地方
内部库存或配额预留；测试环境配置变更；有明确版本号的文档索引发布；可审计的数据修订。后面三类仅是适配器设计方向，尚未由本发行包实现。

## 准入证据
至少能证明：操作员可以撤销未来权限；执行者不能修改批准；观察者不会读取执行者的成功文本作为唯一证据；重复请求不会重复生效；补偿不会覆盖后来者；失败和未测结果有实际负责的人。所有高分之外仍需保留一条可以说“不”的执行路径。
